# あのねジャンプメーカー

写真を置くと、縦テンプレのジャンプに合わせて入れ替わる小さなメーカーです。ファン制作です。本番予定 URL は [https://anone.yoiailabs.com](https://anone.yoiailabs.com) です。写真はサーバーに出さず、この端末の中だけで重ねます。

画面はナナツカゼさんのテンプレの空気に寄せています。太い線、ベタ塗りの色面、少し昔の電子ポップのような夏の残像。よいらぼの紺や金は使いません。フォントは Klee One と Zen Maru Gothic（Google Fonts）です。

## 使い方

1. 写真を数枚選ぶ
2. 「動画の向き」で縦（9:16）か横（16:9）、「エフェクト」でジャンプかズームを選ぶ（2×2 のどれでも）
3. テンプレのベタ塗り背景（緑クロマに限らない）をキーイングして、線画キャラを残す
4. 拍（テンプレのポーズ切替）で写真を差し替える。枚数が足りなければ循環
5. プレビューして MP4 または WebM を保存（オフライン生成）
6. 操作パネルの枠の外の「#あのねジャンプ で X に投稿」でハッシュタグ付きの投稿画面へ
7. その下の「このアプリを共有する」で本番 URL（`https://anone.yoiailabs.com`）を渡す

5 の保存はテンプレをリアルタイム録画せず、30fps の論理時刻でシークして同じ compositor を描き、WebCodecs + mediabunny で映像とテンプレ音声を mux します。WebCodecs が使えないブラウザでは録画に落とさず、Chrome / Edge を案内します。

**縦**はテンプレと同じ 608×1080 です。中央にシャープな 16:9 本編（差し込み写真＋緑クロマを抜いた線画キャラ）を置き、上下帯はその本編フレーム全体を cover した強いブラー＋暗転です（写真だけのブラーではありません）。本編の位置はテンプレ緑帯の実測（y=312–654）に合わせます。

**横**は 1280×720（プレビューと保存で同じ）。上下ブラー帯はなく、キャンバス全体が 16:9 本編です。差し込み写真が背景、線画キャラは前面（白ステッカー縁、公式テンプレと同じ等倍）。公式テンプレは `public/template/landscape.mp4`（1920×1080、X 公式投稿および CapCut 16:9 と同じ映像）です。

## X への投稿

できた動画は `#あのねジャンプ` と `#あのねジャンプメーカー` を付けて X に投稿するのが推奨されています。操作パネルの枠の外の投稿ボタンは最初から押せて、本文に両方のハッシュタグが入った状態になります（`src/share.ts`）。保存済みの動画があれば共有シートに載せ、なければ投稿画面だけ開きます。

- 共有シートが動画ファイルを扱える端末（`navigator.canShare({ files })` が通る iOS / Android）では、保存した動画そのものをハッシュタグ付きで共有シートに渡します。共有先に X を選べばそのまま添付されます。ユーザーが閉じたときは投稿画面を重ねて開きません。
- それ以外（多くの PC ブラウザ）は X の投稿画面（`x.com/intent/post?text=...`）を新しいタブで開くだけです。intent にファイルは載せられないので、保存した動画は手元で添付してもらいます。
- 本文はハッシュタグだけで、このサイトの URL は足しません。動画も本文もサーバーには送りません（投稿は X 側で確定します）。

投稿ボタンの下の「このアプリを共有する」は、Web Share API（`navigator.share({ title, url })`）で本番 URL `https://anone.yoiailabs.com` を渡します。共有シートが無い環境では同じ URL をクリップボードへコピーします。プレビュー URL は使いません。

## 写真の切替（2×2）

向き（縦／横）と切替（ジャンプ／ズーム）は独立に選べます。どの組み合わせでも数値はパネル寸法に対する比なので、同じ系統なら縦横で同じ動きになります。プレビューと保存は同じ `swapFx()` → compositor を通ります。

**ジャンプ**は参考 Short（o1ROhNU0UNw、30fps）をフレーム抽出して SIFT+RANSAC で写真の位置・倍率を測った値です。

- 写真はカット（＝テンプレのポーズ切替フレーム）で「少し小さく（×0.947）・下にずれて（本編高さの 17.5%）」現れ、7 フレで元の位置へ跳ね戻る（位置 (1−k/7)^2.3、倍率 (1−k/7)^2）。
- 7 フレ目から次の拍（15 フレ）へ向けて二次曲線で再び沈む。スロットが 14 フレなら沈み切る前に次のカットが来る。
- カットの瞬間から 3 フレの白フラッシュ（写真層に加算 0.30 ＋スクリーン 0.20、(1−k/3)^2 で減衰）。カット前にはフラッシュは無く、RGB ずれ・ブラーも無い。キャラの黒線はほぼ黒のまま（全面には 0.06 だけ）。
- 沈んでも本編に隙間が出ないよう、写真は 1.32 倍で cover し静止位置を 7% 上に寄せる。

**ズーム**は参考投稿（hagikaze_sami、1280×720・30fps）の実測です。

- 出ていく写真はポーズ切替フレーム S の 3 フレ前から中心へ縮む（S−2: 0.988、S−1: 0.947、S: 0.866）。S ではポーズだけ新しく、写真はまだ前のもの。新写真は S+1 に 1.115 倍で現れ、1 フレごとに (倍率−1) が 0.2 倍になって 4 フレで止まる。キャラは拡縮しない。
- 全面（写真＋キャラ）に横方向のモーションブラー（S−1: 幅の 0.8%、S: 2.7%、S+1: 1.4%）、RGB 横ずれ（R 右・B 左、S で幅の 0.65%）、S で白の加算 0.35（コントラストは保つ）、S+1 で灰かぶり 25%、わずかな行波打ち。
- 縮んだ写真の後ろには同じ写真の cover ぼかしを敷き、黒帯を見せない。

公式の「ナナツカゼ」「あのね」等の文字はユーザー差し込み側に足しません。

画面最下部には参考リンクとして、ナナツカゼさんの X・YouTube・Spotify・Apple Music へのバナーを並べます（`src/links.ts`）。どれも別タブで開き、`rel="noopener noreferrer"` を付けます。公式ロゴの画像は置かず、テンプレに寄せた太線のアイコンを自分で描いてラベルを添えています。

写真の向きは EXIF を `createImageBitmap({ imageOrientation: "from-image" })` で直し、それが落ちる端末では options なしの `createImageBitmap`、HTML Image、FileReader の data URL へ落とします。MIME が空でも拡張子やマジックバイトで JPEG/PNG/WebP なら残します。Android のカメラ写真（HEIC/HEIF）は、ネイティブで読めなければ `heic-to`（libheif）をそのときだけ読み込んで JPEG 相当に変換し、既存の decode へ渡します。変換できない環境では互換性優先（JPEG）かスクショを案内します。JPEG/PNG/WebP の初期読み込みにはデコーダを載せません。WebGL には ImageBitmap を直接上げません（`UNPACK_FLIP_Y_WEBGL` との二重反転を避けるため、Canvas2D に描いてからテクスチャ化します）。読み込み時に長辺 1920 程度へ縮小し、元の巨大画素と File の ObjectURL は持ちません。サムネは別の小さいコピー、decode は最大 2 枚ずつです。写真は端末内のみです。

## 開発

```bash
pnpm install   # または npm install
pnpm dev       # または npm run dev
pnpm test
pnpm build
```

デプロイ（DNS は設定しない）:

```bash
pnpm deploy         # = pnpm build && wrangler deploy（本体 anone）
pnpm dev:worker     # ローカルで Worker + 静的アセットを起動
```

本体 `anone` は Cloudflare Workers の静的アセットとして `dist` を配信します。生成回数（「○回作られたよ」）と `/api/stats`、Durable Object（`GENERATE_STATS` / Worker `anone-stats`）は無料枠を消費していたため削除しました。ページ表示・プレビュー開始・保存の経路から DO は呼びません。

Cloudflare 上に残っている `anone-stats` Worker（クラス `GenerateStats`）は、このリポジトリからは参照しません。クォータを完全に戻すには、ダッシュボードまたは `wrangler delete anone-stats` で一度だけ削除してください。

カット表は向き別のファイルですが中身は同じ拍です（縦横テンプレは同じアニメーション）。

- 縦 `public/template/cuts.json` ／ 横 `public/template/landscape-cuts.json` … 32 スロット。
- 拍の出どころは色分け Short（utNIG60-li0）。テンプレの 10 スロットにそれぞれ単色を入れて書き出したもので、色の切り替わりが写真の切替そのものです。ffmpeg で全フレームを抜き、キャラのシルエット差分の相互相関でテンプレに合わせ（テンプレフレーム＝動画フレーム +1、相関 0.92）、切替は「S−1: 旧色＋白、S: 旧新の混色（ポーズも切替）、S+1: 新色」の 2 フレのディップで、`slots` は S です（`slotFrames`、値は frame/30）。写真の参考 2 本もこれと ±1 フレで一致します（ジャンプは S に新写真＋フラッシュ、ズームは S でブラー頂点・S+1 で新写真）。
- 同じ動画から写真の枚数と並びも取っています。色は 10 種類＝**テンプレは 10 枚**で、32 カットに `A B C D E F G B E A H B A I F I B D H I G H J C H F I J G D A I` の順に入ります（`photoCount` / `slotPhotoOrder`）。メーカーは 10 枚ならこの並びをそのまま使い、11 枚以上は同じ写真が再登場する位置に 11 枚目以降を出た順に入れ、10 枚未満はスロット順にくり返します（並びを剰余で畳むと同じ写真が連続してカットが見えなくなるため）。
- テンプレだけの画素差から拍を拾うのは当てになりません。キャラは 3 フレ刻みの独自の間隔で動くので、写真の切替が最寄りのポーズ切替から 1〜2 フレ外れることがあります（233 と 236、426 と 424 など）。`scripts/analyze-cuts.py` は測った拍と並びを書き出すだけにし、`--check` でテンプレの差分ピークとの位置関係を確認できます。

## キーイング

背景は純緑クロマではなく、ティール・ライム・グレー・赤・紫などフレームごとに変わるベタ塗りです。四隅と上辺から優勢な背景色を毎フレーム推定し、色距離で抜きます。緑が勝つ画素は補助的に抜き、暗い線画は不透明のまま残し、キー色の巻き込み（スピル）を抑えます。WebGL フラグメントシェーダが本線で、未対応時は Canvas2D に落とします。
